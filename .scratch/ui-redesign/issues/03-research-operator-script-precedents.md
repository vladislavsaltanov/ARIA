# Прецеденты сценария оператора: QLab, театр, Spotify/AIMP

Type: research
Status: resolved

## Question

ARIA получает «Сценарий» — рабочий документ оператора в боковой панели: строки с таймкодами, свободным текстом и @упоминаниями треков; клик по строке ставит упомянутый трек в Queue. Как подобные документы смоделированы в существующих инструментах, чтобы не изобретать заведомо хуже?

- QLab (cue lists), театральные суфлёрские/звуковые скрипты (SFX, Show Cue Systems), нотация «музыкальный номер + время + реплика»: как строка привязывается к медиа, как оператор исполняет документ.
- Spotify/AIMP: чем их список воспроизведения отличается от рабочего документа (почему плейлист — не сценарий), что из их UX переносимо.
- Паттерны упоминаний: синтаксис `@`, резолвинг имён к идентификаторам (случаи переименования/дубликатов), автокомплит.
- Таймкоды в документе: абсолютные (время шоу) или относительные (от начала трека)? Как это делают в тетрах/на конференциях (run sheets, rundown: произносят «go»).

Ответ: краткие находки с источниками + 2–3 варианта модели строки сценария с плюсами/минусами каждого.

## Answer

Полный отчёт: [research/03-script-precedents.md](../research/03-script-precedents.md).

- Строка сценария в прецедентах — не строка плейлиста: QLab отделяет cue (действие с target-файлом) от cue number/name и поддерживает Memo cues — «placeholders... in-line notes to the person operating»; театральный prompt book — свободная нотация на полях сценария («no official standard»), cue привязан к моменту реплики, а не к часам.
- Время строки нигде не хранится как абсолютное время суток: первичны порядок+триггер (warning/standby/GO, QLab GO) либо длительность+авторасчёт (Inception rundown: soft/hard time; Shoflo: duration + auto recalculation). Факт пишется кнопкой по ходу шоу («Take Next Story» + Actual Time в Inception, Show Caller Tracking в Shoflo); абсолютный timecode — внешний sync (QLab MTC/LTC c lookback), не поле строки.
- Spotify/Apple Music — демонстративно другая парадигма (прямая цитата QLab-docs: их поведение «disorienting» для cue-оператора): автоплей по порядку, нет GO, нет таймкодов шоу. Переносимо из consumer-UX: duration-колонка, hover-действия, drag&drop, вторичная типографика.
- Упоминания: Slack хранит ID (`<@U012AB3CD>`), имя подставляется при рендере («names... may change at any time... an ID will always remain the same», автопарсинг имён deprecated); Notion хранит ссылку на страницу — переименование отражается во всех упоминаниях автоматически; GitHub: автокомплит по `@` с фильтрацией, Tab/Enter, список ограничен участниками; повисшая ссылка деградирует в плашку, строку не удаляет.
- Модели: (A) Memo-строка — сплошной текст, трек внутри текста; (B) строка-кью со структурированными полями (номер, notation, target, таймкод, trigger); (C) гибрид — свободный текст с упоминаниями-ссылками по `TrackId` + отдельное поле времени строки, записанное кнопкой «пометить сейчас» (elapsed), абсолют — проекция отображения.
- Рекомендация: вариант C — единственный, сохраняющий все функции прецедентов (свободная нотация prompt book, однозначное исполнение как у cue с одним target, факт-время как rundown). Термин: ScriptLine с runs `TextRun | TrackMention(trackId)`; упоминание ссылается на Track (не PlaylistEntry) — Queue/плейлист уже определяют продолжение воспроизведения; переопределения — предмет тикета 07.
- Не проверено (среда): MultiPlay, Stage Research SFX, официальные страницы Spotify/AIMP — их сайты/поисковики недоступны; в отчёте они упоминаются только классификационно.
