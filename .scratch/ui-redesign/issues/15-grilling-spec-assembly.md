# Сборка спеки: структура и нарезка на усилия

Type: grilling

## Question

Все решения карты собраны в Decisions so far. Последний тикет: собрать `spec.md` — дестинацию этой карты.

- Структура спеки: компоновка, Транспорт-бар, Сценарий, Таймеры, Хоткеи, Библиотека, Миграция, Remote-задел — что разделом, что приложением (research-отчёты — ссылками, не копией).
- Нарезка на реализационные усилия: какие срезы кода идут первыми, чтобы после каждого шага приложение оставалось зелёным (опирается на порядок из тикета 13).
- Что из решений требует уточнения деталями прототипов (11, 12) и где эти детали должны попасть в спеку.
- Критерий готовности спеки: реализатор не принимает проектных решений, только следует тексту.

Ответ: spec.md в `.scratch/ui-redesign/` + одна строка в карте о том, что дестинация достигнута. Закрытие этого тикета — конец карты.

## Answer

Спека собрана (2026-09-11): `.scratch/ui-redesign/spec.md` (12 разделов + 3 приложения, ~320 строк).

- Структура: разделы — компоновка, бар, волна/seek/счётчики, громкость/метринг, библиотека/плейлист/очередь, сценарий, хоткеи, настройки, Remote-задел, состояние/данные, миграция+нарезка, риски; приложения — глоссарий, ресерч и прототип ссылками (не копией).
- Нарезка усилий = 5 срезов тикета 13 (каждый зелёный): движок+команды Show → бар → рейка/центр → drawer → настройки.
- Детали прототипов 11/12 вшиты в разделы с пометкой источника (бар 76px, seek по волне, клик-зоны сценария, AIMP-формат, in-app drag); расхождение 05/прототип (крупные часы = show clock) разрешено в пользу прототипа с явной пометкой.
- Открытым оставлен ровно один параметр: числовой порог покраснения LUFS (тюнинг-константа, §12); остальное реализатор берёт из текста без проектных решений.
- Карта закрыта: 15/15, дестинация достигнута.
