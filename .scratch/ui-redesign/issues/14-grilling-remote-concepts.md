# Remote-задел: соответствие понятий веб-пульту

Type: grilling
Status: resolved

## Question

Компоновка (тикет 05) и Сценарий (тикет 07) решены; термины названы и внесены в CONTEXT.md. Решить соответствие понятий для веб-пульта (не реализация — только словарь и состав, который Remote повторяет или отвергает):

- Какие зоны десктоп-компоновки обязательны на пульте: Транспорт-бар, Очередь, Плейлист, Сценарий — что из этого входит в минимальный веб-пульт и что остаётся десктоп-эксклюзивом (например, редактирование Сценария, настройки)?
- LOCK как команда Show (тикет 05): виден ли лок пульту (индикатор? кнопка?), как согласуется с правами пульта (ADR-0005: Remote управляет только Show).
- Mention/TrackId на пульте: рендерить ли упоминания в Сценарии веб-пульта, требует ли этого клиентский API (какой DTO недостаёт).
- Метрики громкости/LUFS: показывает ли пульт мастер-громкость и LUFS (сим из тикета 06) или только транспорт.

Ответ: список «понятие → на пульте / не на пульте» + перечень недостающих DTO/API одним абзацем — раздел спеки, не реализация.

## Answer

Решение пользователя (2026-09-11), четыре развилки: первые три — рекомендованные, по метрикам — расширенная (LUFS тоже на пульт).

**На пульте:**

- Транспорт-бар: play/pause/stop/next, инфозона «играющий + далее», прогресс — команды и партиции уже в протоколе.
- PANIC — уже в протоколе; **обходит лок** (безопасность выше лока, разрешает шина).
- Очередь: просмотр, reorder, удаление, clear — уже в протоколе.
- Плейлист: просмотр с именами (через TrackDigest), активный/перемещение/добавление/удаление/overrides — команды уже в кодеке, имён в Show-партиции не было (см. DTO).
- Сценарий — **только чтение**: строки с временем и именованными упоминаниями, follow-mode по elapsed, смарт-клик строки = исполнение (клиентская логика над существующей `enqueue_track`; несколько упоминаний — выбор на клиенте; 0 — без действия). Редактирование — desktop-only.
- LOCK — только индикатор: Locked-флаг пульт читает из Show-партиции; управляющие команды при локе отвергаются шиной (тот же Rejected, что и на десктопе), исключение — PANIC; лок/анлок — только десктоп-хоткей.
- Мастер-громкость: слайдер + mute (`set_master_gain` и MixerState уже есть).
- LUFS — число + полоска на пульте (решение пользователя, шире рекомендации): сим метрик из тикета 06 публикуется и в протокол.
- Таймеры: show clock + время суток + elapsed трека — Show-партиция по тикету 08, бесплатно.
- Preview: ADR-0005 разрешает пульту, но в минимальный состав не входит — не феасибилен на движке (research 01); в спеке — «разрешён, позже».

**Не на пульте (desktop-only):**

- Библиотека/импорт, разметка CuePoint/Marker (ADR-0005).
- Редактирование Сценария: создание/правка строк, выбор трека для Mention, «пометить сейчас».
- Лок/анлок, настройки и Pairing (QR/пароль), редактор жестов, waveform.

**Недостающие DTO/API (одним абзацем).** Show-партиция пополняется: 1) **Locked**-флагом (тикет 05, лок — команда Show); 2) **Script** — строки: текст, elapsed-время, список Mention с TrackId; опциональные поля, без миграции (тикет 07); 3) **TrackDigest** — лёгкая проекция TrackId → DisplayName по всем Track, присутствующим в Show (плейлисты + очередь + deck + упоминания Сценария): закрывает и имена строк плейлиста, и имена упоминаний на пульте, библиотечную партицию не трогает — граница ADR-0005 цела; переименование Track = Show-дельта с обновлённым дайджестом; Track, удалённый из библиотеки, даёт повисшее упоминание — серую плашку (CONTEXT.md). 4) **Meter-фрейм**: LUFS после сима метрик (тикет 06) RemoteHost транслирует вне версионированных партиций — периодический event-кадр по образцу «position» (latest-value, ~10 Гц, слать только при живых подключениях): непрерывные аудиоданные в версионированный state не входят. **Новых команд нет**: смарт-клик сценария собирается на клиенте из `enqueue_track`, лок разрешает шина (PANIC проходит, остальное — Rejected), follow-mode — клиентская подсветка по elapsed из Show-состояния.
