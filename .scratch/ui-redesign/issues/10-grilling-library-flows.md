# Библиотека: добавление треков и поток в плейлист/очередь

Type: grilling
Status: resolved
Resolved: 2026-09-10
Blocked by: 05

## Question

«Как добавлять треки» пользователь не понял — значит, путь импорта и заведения в плейлист неочевиден. Решить поток целиком:

- Импорт: кнопка + drag&drop из Finder (Avalonia drag-drop), папка целиком, поведение при дубликатах и Faulted-треках.
- Библиотека: список с поиском/фильтром, сортировка; что показываем в строке (имя, длительность, waveform-миниатюра?, пометка Faulted).
- Заведение в работу: перетаскивание в плейлист, двойной клик = enqueue? контекстное меню? Как «ADD TO ACTIVE» и «ENQUEUE» из текущего UI ложатся на новые жесты.
- Плейлист: редактирование порядка (drag&drop против кнопок UP/DOWN), переименование inline против кнопки SET NAME/RENAME (сегодня кнопка RENAME берёт текст не из своего поля — путаница).
- Очередь: где её видно в новой компоновке (решение схемы окна уже есть), как очищается.

Ответ: карта потоков «файл → библиотека → плейлист → очередь» с конкретными жестами и отказами от мета-кнопок.

## Answer

Решение пользователя (2026-09-10), пять развилок HITL, все — рекомендованные. Карта потоков:

```
Finder ──drag&drop──┐
                    ├──► БИБЛИОТЕКА (стеллаж) ──double-click──► ОЧЕРЕДЬ
«+ Import» ─────────┘            │
                                 ├──drag на строку плейлиста ──► ПЛЕЙЛИСТ (вставка в позицию)
                                 ├──drag на очередь ──────────► ОЧЕРЕДЬ (в конец)
                                 └──контекст-меню ──► всё вышеперечисленное + сервис

СКРИПТ (07): клик по упоминанию трека ──► ОЧЕРЕДЬ (тот же жест, что double-click)
ОЧЕРЕДЬ ──go (SPACE)──► ВОСПРОИЗВЕДЕНИЕ ──конец трека──► следующий из очереди
```

1. **Импорт**: два равноправных пути — «+ Import» (диалог мультивыбора файлов и папок) и drag&drop из Finder на стеллаж. Папки рекурсивно по аудио-расширениям. Дубликаты по пути файла — skip, отчёт «добавлено N, пропущено M» без модалок. Faulted-файлы импортируются с пометкой (битость видна, ничего не теряется молча).
2. **Строка библиотеки**: имя, длительность, waveform-миниатюра (лениво из waveform-кэша), метка Faulted. Поиск — подстрока по имени; сортировка имя/длительность/дата. Мультивыбор SHIFT/CMD.
3. **Заведение в работу**: double-click по треку/мультивыбору = enqueue; drag на строку плейлиста = вставка в позицию, drag на очередь = в конец; контекст-меню (в очередь, в плейлист, переименовать, показать в Finder, удалить из библиотеки). Клик по Mention в скрипте (07) = тот же enqueue.
4. **Плейлист**: drag строк — порядок; inline-переименование (double-click по имени / F2); Delete/контекст-меню — убрать строку.
5. **Очередь**: постоянная колонка справа от плейлиста в главном окне; Clear в шапке; после конца шоу остаётся до ручной очистки — никаких автоскрытий.

**Отказы от мета-кнопок**: ADD TO ACTIVE и ENQUEUE умирают (жесты определяют цель; «активный плейлист» как состояние не нужен), RENAME/SET NAME умирают (inline; баг чтения не из своего поля невозможен по конструкции), UP/DOWN умирают (drag), CLEAR QUEUE переезжает в шапку очереди.

Для спеки: drag&drop-цели (стеллаж, строки плейлиста, колонка очереди), ленивые миниатюры из существующего waveform-кэша, отчёт импорта в StatusText-наследнике.

Дополнение тикетом «Прототип главного окна» (2026-09-11, реакция пользователя): AIMP-стиль отображения — в настройках форматирование строки плейлиста: **номер позиции** (пересчитывается при drag-порядке, уже в прототипе), опция **имя файла вместо метаданных**, настраиваемый формат строки.
