# Спека нового десктоп-интерфейса ARIA

Дестинация карты `ui-redesign`. Статус: все 14 тикетов-решений закрыты.
Критерий готовности спеки: сессия-реализатор работает строго по тексту —
проектных решений (что/где/как выглядит и ведётся) здесь не осталось.
Единственный открытый параметр — числовой порог покраснения LUFS-полоски
(тюнинг-константа, §12).

Как читать: разделы 1–11 — нормативная часть (обязательна). Приложения —
ссылки, не копии: глоссарий — `CONTEXT.md`, дизайн-язык — ADR-0006,
ресерч — `research/01..04`, визуальная фиксация плотности — прототип
`.scratch/ui-redesign/prototype/` (запуск — Приложение В).
При конфликте формулировок приоритет: тикет-карта (`issues/`) > прототип >
этот текст не имеет права противоречить ни тому, ни другому.

## 0. Рамка

Пользователь — звукорежиссёр мероприятия. Окно одно, постоянное, без табов:
рейка слева, плейлист в центре, очередь колонкой, транспорт-бар снизу всегда,
сценарий — выезжающая панель справа. Референсы: Spotify (бар, библиотека),
AIMP (форматирование строк, диалог настроек), Nothing (монохром, ADR-0006).
Реализация — за пределами карты; нарезка усилий — §11.

Критерий приёмки спеки целиком: после последнего шага §11 приложение
собирается с нулём предупреждений, `dotnet test` зелёный, каждый жест
разделов 1–8 работает мышью и хоткеем из §7, пульт видит §9.

## 1. Компоновка окна

- Слева постоянная рейка ~260px: секция «Библиотека» (поиск + список треков),
  секция «Плейлисты» (активный помечен полосой), внизу рейки — «Очередь»
  и «+ Import». Рейка узкая, вертикальная; эталон — окно 1440×900, минимум 1100.
- Центр — активный плейлист: шапка (имя, счётчик, поиск-подстрока, кнопка
  «Сценарий», кнопка «?»), строки, справа колонка «Очередь» фиксированной
  ширины (~300, по прототипу) с шапкой и кнопкой Clear.
- Над контентом — блок крупных часов (show clock крупно моноширинно; ниже
  время суток + elapsed трека мелко) и рядом широкая полоса waveform
  играющего трека с курсором. Остаток трека виден также в инфозоне бара
  (позиция/длительность моно). Уточнение прототипом 11 к тикету 05: главный
  крупный показатель над контентом — show clock, а не остаток.
- Снизу постоянный транспорт-бар 76px (§2). Справа поверх контента —
  панель Сценария: SplitView Right Overlay 340px, по умолчанию закрыта (§6).
  Ширина панели регулируется перетаскиванием левого края (240–600, дефолт
  340, найдено прототипом 12); при малом окне панель только перекрывает
  контент, компоновка не сжимается.
- Всегда видны: играющий + следующий, позиции, таймеры, метр, PANIC.
  По требованию: очередь деталей трека (контекст-меню), настройки (диалог),
  help-оверлей (F1).
- Критерий приёмки: ни один элемент §2–§8 не требует скролла окна 1440×900;
  PANIC виден всегда в правом краю бара.

## 2. Транспорт-бар (76px)

Состав строго слева направо:

1. Тонкий прогресс по верхней кромке бара на всю ширину (позиция — из
   PlaybackMonitor, latest-value, вне версионированного state). Индикатор,
   не цель seek (seek — по волне, §3).
2. Инфозона, две строки: имя играющего жирным; серым «Далее: …»
   (оживление мёртвого NextName).
3. Транспорт: Play/Pause — одна кнопка-тумблер 44×44 (иконка по состоянию),
   Stop и Next — 44×44 рядом. Иконки PathIcon (Lucide, fill-геометрия —
   риск из research/04 закрыт прототипом).
4. Правая зона: LUFS-метр (моментальный LUFS числом моно-шрифтом + тонкая
   полоска; за порогом полоска краснеет; при PANIC гаснет, надпись MUTED)
   → громкость (иконка динамика + слайдер ~120px, 0–100% → −80…+12 дБ;
   точные дБ только в тултипе, лицо слайдера — проценты; клик по иконке —
   mute, иконка перечёркивается) → слот таймеров (§3) → индикатор-замок
   (пассивный, тултип «Заблокировать — Ctrl+L») → шестерёнка настроек →
   PANIC (крупнее прочих кнопок, красная рамка — функциональный цвет).
5. Тултипы всех кнопок — «Действие — жест», жесты читаются из HotkeyConfig.

Отказы (больше не кнопки, потому что): Replay — редкое, восстановимое
(Ctrl+R + F1-оверлей); отдельные Play/Pause — слиты в тумблер; LOCK —
хоткей + индикатор (тикет 05); REMOTE/pairing — диалог настроек;
StatusText строкой — исчез (состояние иконкой/цветом).

Критерий приёмки: порядок и размеры зон пиксель-в-пиксель с прототипом;
все тултипы соответствуют таблице §7.

## 3. Волна, seek, счётчики

- Полоса waveform играющего трека — над контентом (§1), данные — peaks из
  существующего waveform-кэша (первое чтение кэша в проде; миниатюры строк —
  лениво из того же кэша). В баре волны нет.
- Seek: клик/драг по волне двигает курсор (уточнение прототипом 11).
- Show clock: стартует первым PLAY после запуска/сброса; паузы, стопы и
  PANIC часы не останавливают и не сбрасывают; сброс только вручную
  (Ctrl+Shift+C + пункт настроек). Elapsed + running-флаг — часть
  Show-state, восстанавливаются после сбоя. Elapsed трека — из
  PlaybackMonitor; время суток — системные часы. Переключателя режимов нет:
  оба показания сразу, слот бара — две строки (show clock крупнее сверху;
  время суток + elapsed трека снизу мелким моно).

## 4. Громкость и метринг (движок → UI)

- Владелец мастер-гейна один: C#-путь SetMasterGain; нативный дубль
  `aria_engine_set_master_gain` удалить. UI читает MixerState; слайдер
  0–100% → −80…+12 дБ (§2).
- Muted-флаг — в состоянии громкости: mute помнит предыдущее значение,
  любое движение слайдера снимает mute.
- LUFS momentary: тап в RenderLoop после ApplyMasterGain + классы
  K-weighting (2 биквад-фильтра на канал, окно 400 мс в преаллоцированном
  ring, гейт −70) — ноль аллокаций, <0.1% CPU, в C#-рендер-пути.
  Публикация метрик движок→UI — сим по образцу PlaybackMonitor
  (latest-value, вне версионированного state).
- Инвариант проекта: ноль аллокаций и ноль локов в аудио-callback/Render
  (тесты `GC.GetAllocatedBytesForCurrentThread` — MixerBusTests, DspNodeTests;
  UI-поток покрыть по их образцу).
- Критерий приёмки: слайдер двигает гейн без кликов; LUFS-число обновляется
  живым звуком; mute/muted-пути покрыты тестами.

## 5. Библиотека, плейлист, очередь

Поток «файл → библиотека → плейлист → очередь»:

```
Finder ──drag&drop──┐
                    ├──► БИБЛИОТЕКА (стеллаж) ──double-click──► ОЧЕРЕДЬ
«+ Import» ─────────┘            │
                                 ├──drag на строку плейлиста ──► ПЛЕЙЛИСТ (вставка в позицию)
                                 ├──drag на очередь ──────────► ОЧЕРЕДЬ (в конец)
                                 └──контекст-меню ──► всё вышеперечисленное + сервис
```

- Импорт, два равноправных пути: «+ Import» (диалог мультивыбора файлов
  и папок) и drag&drop из Finder на стеллаж. Папки — рекурсивно по
  аудио-расширениям. Дубликаты по пути файла — skip, отчёт
  «добавлено N, пропущено M» без модалок. Faulted импортируются с пометкой.
  Канонический движок — `AppHost.ImportTracksAsync` (батч, MergeTracks,
  прогресс); отчёт N/M дописать на движке (нет ни в одном пути).
- Строка библиотеки: имя, длительность, waveform-миниатюра (лениво),
  метка Faulted. Поиск — подстрока по имени; сортировка имя/длительность/
  дата; мультивыбор SHIFT/CMD.
- Заведение в работу: double-click = enqueue; drag на строку плейлиста =
  вставка в позицию; drag на очередь = в конец; контекст-меню (в очередь,
  в плейлист, переименовать, показать в Finder, удалить из библиотеки).
- Плейлист: drag-порядок строк; inline-переименование (double-click по
  имени / F2); Delete/контекст-меню убирает строку. Формат строки (AIMP,
  уточнение прототипом 11, раздел настроек): номер позиции
  (пересчитывается при drag), опция «имя файла вместо метаданных»,
  настраиваемый формат строки.
- Очередь: постоянная колонка справа от плейлиста; Clear в шапке; после
  конца шоу остаётся до ручной очистки; текущий трек подсвечен
  (Transport-партиция).
- Мёртвые мета-кнопки: ADD TO ACTIVE, ENQUEUE, RENAME/SET NAME, UP/DOWN
  умирают; CLEAR QUEUE — только шапка очереди. Активного плейлиста как
  состояния нет: выбор плейлиста в рейке — чистое UI-состояние;
  SetActivePlaylist остаётся командой только для пульта.

## 6. Сценарий

Домен (CONTEXT.md: Script, Mention — канон): на Show может быть несколько
Script (вкладки панели; поправка: мультисценарность вместо решения тикета 07
«один на Show»), каждый — часть версионированного Show-state
с автосохранением, без миграции. Заголовок панели — редактируемое имя сценария (опциональное display-поле Show-state;
дефолт «Новый сценарий»). Строка —
свободный текст + Mention-ссылки на Track по TrackId (хранится ID,
рендерится имя; переименование бесплатно; повисшее — серая плашка).
Время строки — elapsed времени шоу кнопкой «пометить сейчас» (работает
всегда; до старта elapsed = 0); время суток — проекция отображения.
Follow-mode: подсветка строки с временем ≤ elapsed < времени следующей;
таймкоды и show clock — одна система координат. Исполнение (умный клик):
1 упоминание → трек в Queue; несколько → компактный выбор в строке;
0 → заметка. EndAction — обычные правила; повторный клик — снова в конец
Queue. Override'ы — только путём через плейлист.

Взаимодействие (прототип 12, обязательно к повторению):

- Строка: таймкод моно слева, текст с переносом, чипы; повисшее — серое;
  тултип чипа — имя и длительность; hover чипа — подсветка + белая рамка;
  hover строки — play-хинт у таймкода.
- Клик-зоны разделены: клик по тексту = правка строки; фон/таймкод/
  go-кнопка/чип = исполнение (умный клик). Клик по чипу в режиме правки
  убирает упоминание.
- Правка: время — ручное поле («м:сс») + «пометить сейчас» (= elapsed);
  текст — свободный ввод; «@» — Popup-автокомплит (5 треков, клик вставляет
  чип); Enter коммитит строку и открывает новую пустую; кнопка «+ строка»
  во всех состояниях; пустая строка видна тусклым плейсхолдером и правится;
  клик мимо коммитит правку.
- Чип подсвечивает строку трека в библиотеке И в плейлисте (linked-рамка).
- Drag reorder строк с живой линией вставки; разделение строк 8.
- Состояния: 7 строк / 50 строк (шаг ~1:45, ScrollViewer, плотность ~34px
  минимум) / пусто («Сценарий пуст», «Первая строка станет отсчётом шоу»,
  «+ Добавить строку»).
- Закрытие панели любым путём (light-dismiss, крестик, Ctrl+T) коммитит
  открытую правку и уводит фокус из строки (найдено прототипом 12).

Критерий приёмки: сценарий помощника «строка с одним треком исполняется
в очередь; строка с двумя — через выбор; follow идёт за часами» —
без чтения кода.

## 9. Remote-задел (веб-пульт: словарь, не реализация)

На пульте: Транспорт-бар (play/pause/stop/next, «играющий + далее»,
прогресс) + PANIC + Очередь (просмотр, reorder, удаление, clear) +
Плейлист (просмотр с именами, активный/перемещение/добавление/удаление/
overrides — команды уже в кодеке) + Сценарий только-чтение (строки,
follow-mode, смарт-клик поверх существующего `enqueue_track`) + LOCK
только индикатор + мастер-громкость (слайдер + mute) + LUFS (число +
полоска) + таймеры (show clock + время суток + elapsed) + Preview
(разрешён ADR-0005, вне минимального состава — не феасибилен на движке).

Desktop-only: библиотека/импорт, разметка CuePoint/Marker, редактирование
сценария, лок/анлок, настройки и Pairing, редактор жестов, waveform.

Правила: LOCK виден пульту (Locked-флаг из Show); при локе шина отвергает
команды пульта тем же Rejected, исключение — PANIC (обходит лок);
лок/анлок — только десктоп-хоткей.

Недостающие DTO (один абзац для протокола): Show-партиция пополняется
Locked-флагом, Scripts (список Script: имя + строки: текст, elapsed,
Mention с TrackId — опциональные поля, без миграции) и TrackDigest (проекция TrackId →
DisplayName по всем Track Show: плейлисты + очередь + deck + упоминания;
переименование = дельта дайджеста; удалённый из библиотеки = повисшее
упоминание); LUFS RemoteHost транслирует вне версионированных партиций —
периодический event-кадр по образцу «position» (latest-value, ~10 Гц,
только при живых подключениях). Новых команд нет: смарт-клик собирается
из `enqueue_track`, follow — клиентская подсветка по elapsed.

## 12. Риски и открытые параметры реализации

- Нативный DnD Avalonia 12.1.2 на macOS нерабочий (DoDragDropAsync из
  PointerPressed мгновенно возвращает None; in-process формат крашит
  NSDraggingSession «0 pasteboard items, 1 drag image»). В прототипе —
  in-app drag на pointer capture. Продакшен: апгрейд/фикс Avalonia либо
  свой DnD; раздел drag&drop §5 от этого не зависит (жесты те же).
- Порог покраснения LUFS-полоски — единственный открытый числовой
  параметр: константа реализации, дефолт в диапазоне −18…−12 LUFS
  momentary, зафиксировать в коде.
- Песочница (проверено): нативные экзешники живут только под `bin/`;
  loopback Remote-тесты флакают под нагрузкой — перезапуск (продукт
  ни при чём, коммит 95e07be).
- Waveform-кэш читается в проде впервые (§3, §5): ленивые миниатюры,
  курсор — styled property с AffectsRender (research/04).
- Иконки fill-геометрией (риск research/04) — закрыт прототипом
  (15 иконок, selftest 26/26).

## Приложение В. Прототип

`.scratch/ui-redesign/prototype/` (ARIA.Prototype, Avalonia 12.1.2, вне
солюшена): рейка 260 / центр / очередь 300 / бар 76 / drawer 340 Overlay /
F1-оверлей / drag-потоки / drawer сценария на данных (7/50/новый).

`ARIA.Prototype --selftest`. Прототип — визуальная фиксация плотности;
при расхождении с текстом спеки прав текст спеки.
