# Метки на seek-панели — дизайн

Дата: 2026-10-12. Режим: Operate. Поверхность: PlaybackHeader (волна).

## Намерение

Оператор размечает файл по ходу работы: ставит именованные метки прямо на
волне, видит их на таймлайне, прыгает по ним, двигает, удаляет и откатывает
правку. Метка — точка автостопа (`MarkerAction.Stop`): шоу должно
останавливаться в размеченной точке, а не «где-то там».

Зачем сейчас: разметка файла есть в домене, БД и аудио-движке, но в
интерфейсе её нет вообще — оператор не может поставить метку ничем, кроме
правки JSON руками.

## Что уже есть (проверено в коде)

| Слой | Состояние |
| --- | --- |
| Домен | `Marker(Name, Position, MarkerAction)` — `src/ARIA.Core/Model/Playback.cs:40`; `TrackDefaults.Markers` — `Track.cs:10` |
| Эффективные настройки | `EffectiveSettings` берёт метки **только с Track** — `PlaybackSettings.cs:32`; у `ProjectOverrides` поля нет |
| Персистентность | SQLite: `LibraryStore.cs:57` (track), `Mappers.cs:193`/`203`; show.json: `Mappers.OverridesDto` |
| Движок | `StreamEndReason.StoppedByMarker` — `MixerBus.cs:472`, но `ScanCutoff` читает **только `markers[0]`** — `MixerBus.cs:463` |
| Передача в движок | метки уходят в `StreamOptions` в трёх местах старта потока — `ShowController.cs:743`, `1173`, `1968`; живой правки нет |
| Команды | команд для меток нет (`Commands.cs`, 147 строк) |
| Отмена | нет |
| Интерфейс | волна — `PlaybackHeader.axaml` + `.axaml.cs` (протяжка = seek); тесты headless есть |

## Решения

Выбор пользователя:

1. Метки переопределяются на **PlaylistEntry** (как cue-точки по ADR 0001).
2. Движок: **все** метки + **live re-arm** при правке.
3. Отмена — **в Core, на уровне команд**.
4. Редактор имени — **TextBox поверх канваса**, Enter/Esc.

Мои решения (builder calls — проверять при чтении):

- Seek-панель — это волна в `PlaybackHeader`, а не 3px полоса прогресса в
  `TransportBar`. Если имелась в виду полоса — дизайн переигрывается.
- Жесты на метке: ЛКМ — переход, 2×ЛКМ — редактор имени (ЛКМ занята
  переходом), ПКМ без движения (<3px) — удалить, ПКМ с движением — сдвинуть.
- ПКМ на пустой волне ставит метку в точке нажатия и сразу открывает редактор.
- Имя метки видно всегда под меткой, время — всегда над меткой. Скученность:
  если до предыдущей видимой метки меньше 28px, имя поздней не рисуется,
  время рисуется. Правило детерминированное и тестируемое.
- Полоса меток резервируется всегда: 14 (время) + 56 (волна) + 14 (имя).
  Шапка не прыгает при появлении первой метки.
- Правка меток играющего вхождения пишет override на это вхождение; если
  играет не вхождение (Queue или Track), пишет дефолт Track. Выбор
  «сделать дефолтом для файла» в этот срез не входит.
- Стек отмены: 64 операции, живёт в сессии, только операции с метками.
  Redo нет.
- Пустое имя подставляет интерфейс («Метка N»), Core пустое имя отвергает.
- Пределы: имя ≤ 48 символов, ≤ 64 метки на файл, позиция в [0, duration].

## Контракты

### Модель

```csharp
public sealed record ProjectOverrides(
    string? Name = null, string? Color = null, string? Note = null,
    double? GainDb = null, EndAction? EndAction = null,
    Fade? In = null, Fade? Out = null,
    TimeSpan? CueIn = null, TimeSpan? CueOut = null,
    TrackAudioSettings? Audio = null,
    ImmutableArray<Marker>? Markers = null);
```

`null` — наследовать метки Track; пустой массив — вхождение без меток.
`EffectiveSettings.Resolve`: `Markers: o?.Markers ?? d.Markers ?? Empty`.
`ForTrack` без изменений.

### Команды

```csharp
public sealed record SetTrackMarkers(TrackId Track, ImmutableArray<Marker> Markers) : Command;
public sealed record SetEntryMarkers(EntryId Entry, ImmutableArray<Marker>? Markers) : Command;
public sealed record Undo : Command;
```

### Валидация

`MarkerValidation.Validate(ImmutableArray<Marker> markers, TimeSpan duration)` →
`string?` причина: `marker-name-empty`, `marker-name-too-long`,
`marker-position-out-of-range`, `marker-too-many`. Рядом с `AudioValidation`.

### Движок

```csharp
void SetMarkers(StreamHandle handle, ImmutableArray<MarkerSpec> markers); // default no-op в IAudioEngine
```

`CommandKind.SetMarkers` в очереди микшера, поле `MarkerSpec[]? Markers` в
`MixerCommand` (массив выделяется при постановке в очередь, не в Render).
`MixerVoice`: `Markers` становится изменяемым, добавляется `MarkerIndex`.

## Поведение движка

- Метки сортируются по позиции при создании voice (`MixerBus.AddVoice`, вне
  аудио-потока). Сейчас порядок — как пришёл.
- `ScanCutoff` идёт по индексу: на входе в блок индекс сдвигается мимо меток,
  чья позиция уже пройдена; в цикле по кадрам остановка происходит на первой
  непройденной метке.
- **Изменение поведения:** переход за метку больше не останавливает
  воспроизведение (сейчас `MixerBus.cs:470` останавливает: `filePos >=
  markerPos`). Смысл метки — «остановись, когда дойдёшь», а не «остановись,
  если оператор уже ушёл дальше». Нужен тест на оба поведения.
- `SetMarkers` меняет метки живого потока: без переармливания, без разрыва
  звука, ноль аллокаций в Render.

## Интерфейс

Полоса волны становится трёхрядной (сверху вниз): время метки 10 моно,
волна 56, имя метки 11 моно.

- Метка: линия 1px полной высоты волны + ромб 7×7 у верхней кромки. Цвет —
  `BrushDim`, на наведении `BrushFg`. Янтарь не используется: янтарь в
  шапке значит «идёт эфир», метка — статичная разметка.
- Время над меткой: `mm:ss.d`, 10 моно, `BrushDim`, центрируется по метке,
  прижимается к краям полосы.
- Имя под меткой: 11 моно, `BrushDim`, та же привязка. В режиме
  редактирования — TextBox с автфокусом, шириной по содержимому (мин. 80).
- Наведение: метка светлеет, подсказка `ToolTip` —
  «ЛКМ — перейти · 2×ЛКМ — переименовать · ПКМ — удалить · ПКМ+протяжка — сдвинуть».
- Метка под курсором определяется по расстоянию ≤ 4px по X; при совпадении
  выигрывает ближайшая.
- Состояние протяжки: пока тянут метку, время над ней показывает целевую
  позицию (как протяжка волны показывает превью позиции — DESIGN.md,
  Surfaces/PlaybackHeader).
- Пусто (нет трека, нет меток) — полоса выглядит как сегодня, ряды пустые.

## Края

| Случай | Поведение |
| --- | --- |
| Трека нет | метки не рисуются, ПКМ ничего не делает |
| Длительность 0 | постановка запрещена (нет позиции) |
| Метка на 0 или на duration | разрешена, линия прижата к краю, текст прижат внутрь |
| Имя пустое после коммита | «Метка N» (N — порядковый номер), команда уходит с этим именем |
| Esc в редакторе | метка, поставленная этим жестом, не создаётся |
| Правка существующей метки, Esc | прежнее имя остаётся |
| Сдвиг за пределы волны | позиция зажимается в [0, duration] |
| Сдвиг закончился в 1px от исходной точки | считается кликом → удаление |
| Скученные метки (<28px) | имя поздней не рисуется |
| Метки в одной точке | обе видны, автостоп срабатывает на первой, вторая — на следующем старте после неё |
| Правка на ходу | движок получает новый массив сразу, звук не прерывается |
| Отмена | восстанавливает прежний массив (создать/переименовать/сдвинуть/удалить) |
| Отмена при пустом стеке | команда отвергается как `nothing-to-undo` |

## Тесты

- `Core.Tests`: приоритет override (entry перебивает track, пустой массив
  снимает метки, null наследует); валидация (пустое имя, длинное имя,
  позиция вне файла, 65 меток); `SetTrackMarkers`/`SetEntryMarkers` меняют
  состояние и шлют `SetMarkers` в движок, если трек играет; отмена каждого
  из четырёх видов правки; отмена пустого стека отвергается; отмена не
  пишется в стек повторно.
- `Audio.Tests`: остановка на второй метке после старта между первой и
  второй; переход за метку не останавливает; `SetMarkers` живого потока
  меняет точку остановки; тест нулевых аллокаций в Render остаётся зелёным.
- `Persistence.Tests`: метки вхождения переживают запись/чтение SQLite и
  show.json; старый JSON без меток читается как `null`.
- `App.Tests` (headless): ПКМ ставит метку и открывает редактор; Enter
  коммитит имя и шлёт команду; Esc не создаёт метку; ЛКМ по метке шлёт
  `SeekTo`; ПКМ по метке без движения удаляет; ПКМ+протяжка шлёт сдвиг;
  `Ctrl+Z` шлёт `Undo`; скученные метки не рисуют второе имя.
- `Remote.Tests`: `set_entry_overrides` с `markers` в JSON сохраняет метки;
  без поля — не падает.

## Не входит в срез

- Редактор меток в браузере (только сохранение чужих правок).
- Live re-arm меток канала Preview.
- Redo, отмена команд кроме меток, отмена, переживающая перезапуск.
- Метки в строках Queue и списках, мини-карта меток.
- Постановка метки с клавиатуры (hotkey) — кандидат на следующий срез;
  сейчас разметка доступна только мышью.
- Выбор «вхождение или файл» при постановке.

## Риски

- 28px — эвристика; на узком окне (1100px) и 3-минутном файле метки
  скучиваются и имена пропадают. Лечится зумом волны — не в этом срезе.
- Изменение поведения движка (переход за метку) затрагивает тех, кто уже
  размечал файлы руками через JSON; считается исправлением.
- Стек отмены в памяти: падение приложения отмену теряет, метки уже
  сохранены.
