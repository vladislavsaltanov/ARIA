# Пульт в LAN: статическая пара идентификатор/пароль, bind по умолчанию

RemoteHost по умолчанию слушает LAN-интерфейсы (IPv4 Any), а доступ пульта определяется **Pairing** — статической парой «идентификатор + пароль» из `remote-auth.json` в данных хоста, автогенерируемой при первом старте. `POST /auth` по паре выдаёт сессионный токен, WS принимает только его (legacy `?token=` остаётся только для loopback-запуска без credentials); не-loopback bind без credentials запрещён на старте. Пароль хранится в файле данных хоста открытым текстом (позиция прежнего `remote-token.txt` не меняется: угроза — пиры LAN, а не локальные файлы), отображается в панели и вшивается в QR, сброс генерирует случайный новый и инвалидирует прежний QR.

Considered Options: PBKDF2-хэш вместо plaintext — отклонён: без plaintext невозможны повторный показ в панели и QR с ключом, а локальный файл и так за пределами угрозы; TLS/сертификаты — отклонены как несоразмерные для домашней LAN (пароль идёт по HTTP — принятый риск, rotation дешёвая); числовой PIN — отклонён: длинный алфавитный пароль ставится в QR и не требует набора, PIN ограничивает энтропию; cap неудачных попыток (lockout) — отклонён: DoS против самого оператора важнее, брутфорс уже замедлен фиксированной задержкой 300 мс на неудачу; одноразовые токены — отклонены: переподключения пульта при сбоях сети — норма, повторный ввод на телефоне в самый ответственный момент недопустим.

Consequences: перезапуск хоста сбрасывает сессионные токены (пульт переподключается автоматически по сохранённой паре); смена или сброс пароля инвалидирует напечатанный QR — нужно пересканировать.
