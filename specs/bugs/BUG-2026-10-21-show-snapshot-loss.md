# BUG-2026-10-21-show-snapshot-loss: один битый/несогласованный show.json стирает шоу оператора

## Problem

- Actual:
  - `JsonSnapshotStore.Save` писал без `fsync`. При потере питания на APFS/ext4 после rename может остаться пустой или рваный файл.
  - `LoadLatest` на битом файле молча возвращал `null`; ловились только `JsonException`/`IOException`, а `"Tracks": null` давал `NullReferenceException`, который рушил старт.
  - Любая несогласованность (висячий элемент очереди, дубль id, вхождение без трека, gain вне диапазона) приводила к отказу `RestoreShow` целиком.
  - Во всех трёх случаях первый же автосейв перезаписывал `show.json` пустым шоу: данные оператора терялись безвозвратно.
  - Автосейв полностью переписывал SQLite-библиотеку (DELETE всех таблиц + INSERT) на каждую дельту шоу, в том числе на тик часов шоу раз в секунду: постоянная нагрузка на диск всё шоу.
- Expected: сохранение переживает обрыв питания; битый файл сохраняется для разбора, восстановление идёт из предыдущего поколения; несогласованный документ ремонтируется, а не выбрасывается; библиотека пишется, только когда изменилась.

## Fix

- `Save`: запись во временный файл, `Flush(flushToDisk: true)`, `File.Replace` с поколением `show.json.bak`.
- `LoadLatest`: основной → `.bak`; каждый нечитаемый файл копируется в `show.json.corrupt-<ts>`; ловится любое исключение разбора; null-коллекции в JSON читаются как пустые.
- `ShowDocumentRepair.Repair`: дедуп треков, отбрасывание висячих/дублирующихся вхождений и элементов очереди, сброс неизвестного ActiveId, клемп gain/panic-fade/clock. Согласованный документ возвращается тем же экземпляром. `AppHost` ремонтирует документ до `RestoreShow` и пишет в лог `snapshot.repaired`.
- `ShowAutosaver`: `Upsert` библиотеки пропускается, если треки и проекты те же (ссылочное равенство неизменяемых массивов) и прошлый upsert удался; флаг `_disposed` отсекает таймерный flush после Dispose.
