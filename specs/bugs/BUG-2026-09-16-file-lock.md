# BUG-2026-09-16T180000: удалённый из проекта трек держит файл открытым

## Problem

Actual: трек воспроизвели хотя бы раз, удалили из проекта — файл остаётся открыт процессом ARIA.App. ОС не даёт переместить/переименовать/удалить. Помогает только перезапуск.

Expected (ТЗ 2.2): после стопа и удаления трека дескриптор освобождается; файл сразу доступен ОС; проверяется при удалении трека, переключении, стопе, закрытии проекта, ошибке воспроизведения.

Repro: play трека → stop → удалить трек из проекта → удалить файл средствами ОС → отказ.

Security impact: NONE. Локальные файловые дескрипторы, trust boundary не пересекается.

## Root Cause Analysis

Путь: движок открывает декодер на файл → голос микшера владеет источником до конца жизни → освобождение идёт командой Remove с фактическим удалением голоса на render-пути.

Почему файл не освобождается (проверено чтением кода, scout-отчёт в сессии):

1. Главная дыра: миксер никогда не закрывает источник. Завершение/удаление голоса только снимает флаги и выкидывает голос из списка — Dispose источника не вызывается нигде на этом пути. Источник без финализатора — нативный декодер и fd живут вечно даже после корректного освобождения голоса.
2. Упавший отложенный голос не освобождается: для retired-голоса с Faulted хендл только вычёркивается, Dispose не зовётся.
3. Удаление записи/плейлиста не трогает движок: меняется только модель, текущий/queued голос продолжает держать файл. Сценарий ТЗ воспроизводится именно так.
4. Контрибьютор: всё освобождение асинхронное (команда → render-тик), синхронного закрытия на control-потоке нет — тест на «сразу удалить» должен учитывать тик.

Не регрессия. Дизайн-дефект владения ресурсом.

## Prior Art (research-first)

- Своё: краткоживущие владельцы (импорт, сканнер, замер LUFS) закрывают через using — вердикт extend того же приёма на голоса микшера.
- Своё: retired-хендлы с fade уже откладывают Dispose до Ended — вердикт compose (та же точка для Faulted).
- Новое: закрытие должно происходить на render-пути владения (где голос умирает), не на control-потоке — вердикт build без новых зависимостей.
