# BUG-2026-09-16T170000: вис при потере доступа к воспроизводимому файлу

## Problem

Actual: трек играет (файл качается через торрент-клиент), клиент закрывают → приложение перестаёт отвечать: трек не играет, переключение и транспорт мёртвые, помогает только перезапуск.

Expected (ТЗ 2.1): потеря доступа к файлу не блокирует интерфейс; проблемный трек останавливается; пользователь видит понятное сообщение; другие треки запускаются; ошибка пишется в лог; перезапуск не нужен.

Repro: играть трек, чей файл исчезает mid-stream (или чей open висит на мёртвом маунте).

Security impact: NONE. Локальный playback-контур, trust boundary не пересекается, exploit path отсутствует.

## Root Cause Analysis

Путь: команда Play → шина управления → контроллер синхронно открывает источник в движке на control-потоке → render-поток тянет фреймы → ошибка открытия превращается в отложенное событие Faulted → контроллер останавливает транспорт и метит fault.

Почему падает (проверено чтением кода, scout-отчёт в сессии):

1. Главная дыра: обрыв mid-stream неотличим от конца файла. Короткое/нулевое чтение маппится в Completed → автопереход на следующий трек вместо Faulted+Stop. Миксер архитектурно не умеет испускать Faulted — единственный продюсер Faulted это fault-at-open. Причина теряется на стыке декодер→миксер.
2. Открытие источника синхронное на control-потоке (pump). Мёртвый сетевой/отмонтированный диск блочит open на таймауте ФС → вис всего управления.
3. Код ошибки открытия схлопнут в null (нет файла vs битый vs неподдержанный неразличимы) → UI вынужден гадать через проверку существования файла в UI-потоке, которая на мёртвом маунте тоже блочится.

Контрибьютор: fake-движок в core-тестах всегда открывает успешно — синхронный open-failure и mid-stream обрыв тестами не покрыты; fault только инжектом события.

Risk level: Medium. Трогаем render-путь и контракт источника сэмплов; поведение меняется только на ошибочных чтениях, ранее не покрытых.

Не регрессия. Дизайн-дефект обработки ошибок.
