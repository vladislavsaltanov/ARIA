# BUG-2026-09-16T210000: дроп папки на боковое меню не создаёт плейлист

## Problem

Actual: перетаскивание папки внутрь плейлиста импортирует треки в текущий плейлист, а дроп папки на боковое меню (список плейлистов) не делает ничего — новый плейлист не создаётся.

Expected: дроп папки на боковое меню создаёт новый плейлист по имени папки и импортирует в него найденные треки (лайт ТЗ 3.3 в эпоху плейлистов). Дроп отдельных файлов — в текущий/выбранный плейлист как раньше.

Repro: перетащить папку с аудио на панель «Плейлисты» → ничего не происходит.

Security impact: NONE. Тот же конвейер импорта, новая только точка входа.

## Root Cause Analysis

Путь: OS-drop обработан только в центре (PlaylistCenter.OnFilesDropped → ImportAudioFilesAsync в выбранный плейлист). У бокового меню (RailPlaylists) нет AllowDrop/обработчиков вообще — событие уходит в пустоту.

Почему ничего нет (проверено чтением кода): механизм создания плейлиста с awaited-именем и импорт по папке (рекурсия в хосте) уже существуют — не хватает только VM-метода «папки → новые плейлисты» и wiring дропа в rail. Дедуп имени (папка с занятым именем) и «в папке уже есть проект → предложить открыть» — скоуп эпохи Проекта (ТЗ 1.1/3.3), здесь уникализируем имя.

Не регрессия. Недореализация точки входа.
