# BUG-2026-10-20-marker-pause-fade: пауза на метке режет звук вместо плавного затухания

## Problem

- What happens: при достижении метки с действием `Pause` звук обрывается мгновенно
  (щелчок), хотя в настройках движка задан «скорость затухания» (stop fade).
  Кнопка паузы и кнопка стоп в той же ситуации гаснут плавно.
- What should happen: голос затухает до метки за время, заданное в настройках, и
  транспорт встаёт ровно на метке.
- How to reproduce: включить сглаживание, задать «скорость затухания» > 0, поставить
  метку с действием «Пауза», дождаться её — громкость падает скачком.
- Security impact: NONE — локальный playback-путь, exploit path отсутствует.

## Root Cause Analysis

- Обрывает голос **движок**, а не контроллер: `MixerBus.ScanCutoff` при пересечении
  метки возвращает `StreamEndReason.StoppedByMarker`, и render-поток сразу вызывает
  `EndVoice` — фейдер не участвует, амплитуда падает в ноль за один блок.
- Все остальные пути остановки идут через фейдер, поэтому звучит плавно:
  - пауза кнопкой — `Transport(Pause)` → микшер ставит рампу вниз на `_pauseFadeFrames`
    и глушит голос после её завершения;
  - стоп кнопкой — `SetMix(..., FadeSpec(StopFade, …, StopWhenDone: true))`;
  - кроссфейды (перемотка, автосмена) — `FadeSpec` на уходящем голосе.
  Длина паузной рампы — это и есть «скорость затухания» из настроек: движок получает
  её как `SetSmoothing(StopFade, StartFade, enabled)`.
- Контроллер на маркерную паузу реагирует уже **после** смерти голоса
  (`ApplyMarkerAction` → `PauseDeckAt` → переоткрытие потока в позиции метки), поэтому
  «затухание» там применить не к чему: FadeSpec на мёртвый голос ничего не даёт.
- Отсюда вывод: затухание обязано происходить **до** пересечения метки, внутри движка.

## Follow-up: персональные настройки у каждой метки

Требование оператора: у каждой метки свои настройки затухания — унаследованные
глобально или переопределённые свои, по образцу треков.

Наблюдения по текущей модели:

- Трек: `TrackDefaults` (наследование) + `ProjectOverrides` (переопределение),
  сведение в `EffectiveSettings.Resolve` — `o?.In ?? d.In ?? Fade.None`.
- Метка: `Marker(Name, Position, Action)` — набора у метки нет вовсе; сам список
  меток наследуется целиком (`ProjectOverrides.Markers` заменяет список трека целиком,
  а не поле-в-поле).

Что понадобится:

- Модель: `Marker(..., Fade? Fade = null)` (или отдельное поле длительности/кривой
  затухания) + правило сведения «своё ?? глобальное (stop fade из настроек)».
- Движок: длительность затухания должна доезжать до метки — `MarkerSpec` получает
  поле длительности, микшер берёт её из ближайшей метки вместо общей.
- Персистентность: `TrackDefaults.Markers` и `ProjectOverrides.Markers` уходят в
  SQLite, show.json, формат проекта (ZIP) и кодек пульта — новое поле требует
  правки мапперов, DTO и обратной совместимости (старые данные → наследование).
- Интерфейс: редактор метки (попап) — поле длительности затухания и «наследовать /
  задать своё».
- Ветвление: per-marker fade должен уметь переопределять и глобальный stop fade, и
  трековый `Out` (сейчас длительность `Out` трека не используется вовсе — берутся
  только кривые).

Оценка: это отдельная сквозная задача (модель → движок → персистентность → пульт →
интерфейс), а не правка в одном месте. Спеку и оценку готовить отдельно.
