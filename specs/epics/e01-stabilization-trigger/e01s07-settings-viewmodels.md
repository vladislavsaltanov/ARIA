# Story e01s07: Настройки — секционные VM и пункты из данных

**type:** refactor
**risk:** P1
**context:** domain

**Context**: После e01s06 секции лежат отдельными
файлами, но делят god-VM (393 строки): новый пункт =
правка монолита. Стори режет VM по секциям и ведёт
однотипные пункты из дескрипторов.

## Zoom-out

- **Purpose**: секция владеет поведением и пунктами;
  родитель — шина, стор, композиция.
- **Callers**: секции e01s06, тесты Settings*.
- **Contracts**: персист-семантика 1:1 (каждый save
  пишет полный DTO, как сегодня); порядок сабмитов
  тот же.

## Requirements

#### MODIFIED: Поведение настроек живёт в секциях

**Before:** Один `SettingsViewModel` на все пункты;
тесты привязаны к god-классу.
**After:** `ViewModels/Settings/`: Gestures, Engine,
Playback, RowFormat, Clock; тесты переехали за кодом
1:1; новый пункт = свойство или строка дескриптора.

## Steps

1. Секционные VM + композиция, тесты переехали 1:1
   → verify: `dotnet test tests/ARIA.App.Tests
   --filter Settings`
2. Слайдеры движка из дескрипторов (label/min/max/
   get/set), новый слайдер = 1 строка
   → verify: `dotnet build`
3. Headless: смена в секции персистит и шлёт в шину
   → verify: `dotnet test tests/ARIA.App.Tests
   --filter SettingsDialog`
4. Полный прогон
   → verify: `dotnet test`

## Verification Script

1. Движок: крути слайдеры — значения держатся,
   рестарт сохраняет.
2. Жесты/формат/часы — как раньше.
3. В коде: новый пункт движка добавляется 1 строкой.
